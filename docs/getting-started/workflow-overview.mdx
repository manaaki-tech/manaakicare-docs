This page provides visual diagrams to help you understand how <Term path="referral" plural /> and <Term path="serviceEpisode" plural /> flow through Manaaki Central. These diagrams are useful for new staff orientation and understanding the end-to-end process.

### <Term path="referral" /> Intake Steps

The intake form is a three-step wizard. Each step must be completed before the next unlocks:

| Step | Label | What is captured |
|------|-------|-----------------|
| 1 | Intake | Client, referrer, service and reason for <Term path="referral" /> |
| 2 | Consent | How consent was obtained, and what was provided to the client |
| 3 | Review & Submit | Read-only confirmation, then submit and dispatch to a service |

The <Term path="referral" /> record is created at the **end of Step 1**, not at final submission — from that point it exists with a reference number and **Draft** status and can be returned to later.

Once all three steps are complete and the entry is submitted, it moves to **Pending Service Dispatch**.

For the full walkthrough see [Creating a Referral](/referrals/creating-a-referral).

### Role Quick Reference

| Role | Primary Responsibilities | Dashboard Focus |
|------|-------------------------|-----------------|
| **Intake Officer** | Search/create clients, complete 3-step intake, dispatch to services, can directly assign <Term path="caseWorker" plural /> | New <Term path="referral" plural />, review queue, service dispatch |
| **Head of Intake / Intake Officer** | Review all <Term path="referral" /> information and submit review | Review queue, pending reviews |
| **Supervisor / Program Manager** | Approve/reject service requests, select <Term path="caseWorker" plural /> on approval, monitor team | Pending service reviews, team <Term path="activity" /> |
| **<Term path="caseWorker" />** | Activate service episodes, deliver services, record activities, close episodes | Active <Term path="cases" />, follow-ups due, client interactions |

Different priorities have different expected response times.

```mermaid
    emergency --> r1
    crisis --> r2
    urgent --> r3

```

### Priority Guidelines

There are five priority levels. The <Term path="referral" /> form shows the expected response time against each one as you select it.

| Priority | Response time | When to Use | Example Scenarios |
|----------|---------------|-------------|-------------------|
| **Emergency** | Now | Immediate safety concern requiring emergency response | Child at risk, medical emergency |
| **Crisis** | 4 hours | Crisis situation, handle urgently | Acute family breakdown, imminent harm |
| **Urgent** | 24 hours | Needs attention within a day | Family in distress, time-sensitive support needed |
| **Priority** | 3 days | Important but not an emergency | New client intake, scheduled assessment overdue |
| **Routine** | 5 days | Standard processing | Regular check-in, administrative <Term path="referral" /> |

## Status Reference

All status values used across the system, grouped by lifecycle. These are the values you will see in badges, filters, and reports.

### Referral statuses

These statuses track where an entry is in the intake-to-allocation pipeline.

| Status | Description |
|--------|-------------|
| **Draft** | Entry is being created — intake step 1 in progress |
| **Pending Consent** | Intake step 2 — awaiting consent and agreement |
| **Pending Review** | All intake steps complete, awaiting review submission |
| **Pending Service Dispatch** | Review complete, ready for service selection and allocation |
| **Pending Service Review** | Service request sent to supervisor/programme manager for approval |
| **Accepted Pending Allocation** | Service approved by manager, <Term path="caseWorker" /> selection pending |
| **Allocated Awaiting Service** | <Term path="caseWorker" /> assigned, service episode created and ready to commence |
| **Cancelled** | Entry cancelled before a service episode began |
| **Withdrawn** | Client withdrew before a service episode began |

### Service episode statuses

Once a referral is allocated, a service episode is created and moves through its own lifecycle.

| Status | Description |
|--------|-------------|
| **Awaiting Staff Assignment** | Service episode created, no <Term path="caseWorker" /> yet confirmed |
| **Awaiting Commencement** | <Term path="caseWorker" /> assigned, waiting for them to activate the episode |
| **Active / In Progress** | <Term path="caseWorker" /> has activated the episode — service delivery is underway |
| **On Hold** | Delivery temporarily paused (e.g. client unavailable, waiting on external factor) |
| **Completed** | Service episode successfully concluded |
| **Closed** | Episode closed without full completion (early closure or termination) |

### Consent statuses

Consent is tracked separately from the referral status and may change at any point.

| Status | Description |
|--------|-------------|
| **Consent Active** | Client has given consent and it remains in force |
| **Consent Withdrawn** | Client has withdrawn their consent — service delivery should not proceed |

:::warning
If a client's consent is withdrawn at any stage, check with your supervisor before taking any further action on their record.
:::
